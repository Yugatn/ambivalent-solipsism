# Синема Катарсис — Scientific Contentometry Protocol v0.2

**Статус:** research protocol / methodological prototype  
**Принцип:** measurement before interpretation

## 1. Назначение и эпистемическая граница

Протокол определяет методологию «Синема Катарсис» как системы измерения медиастимула и отдельной экспериментальной инфраструктуры для исследования реакций Субъекта.

Пять уровней строго разделяются:

CONTENT → EXPOSURE → RESPONSE → EFFECT → HARM

- **Content** — что предъявлено.
- **Exposure** — как, сколько и в каком контексте это предъявлено.
- **Response** — измеримое изменение физиологического, субъективного, когнитивного или поведенческого показателя.
- **Effect** — воспроизводимое изменение относительно контроля/базовой линии, интерпретируемое в рамках конкретного дизайна.
- **Harm** — неблагоприятный исход, требующий отдельной операционализации и доказательной базы.

Следовательно:

CONTENT ≠ RESPONSE ≠ EFFECT ≠ HARM

Наличие стимула не доказывает реакцию. Реакция не доказывает вред. Корреляция не доказывает причинность.

---

## 2. Архитектура объекта

MEDIA → SHOT → EVENT → MPE → RELATION → EXPOSURE

### L0 — Observation

Наблюдаемые примитивы: объект, человек, лицо, действие, движение, звук, речь, текст, цвет, жест, локация.

### L1 — Event

Композиция наблюдений в событие.

Пример:

PERSON + BOTTLE + DRINKING

**SHOT ≠ EVENT.** Одно событие может продолжаться через несколько планов.

### L2 — Media Program Element

Событие, сопоставленное с версионируемой онтологией.

Пример:

consumption.alcohol

### L3 — Relation / Context

Связи между субъектами, объектами, событиями, локациями, последствиями, последовательностью и социальным контекстом.

### L4 — Exposure Profile

Формальная характеристика предъявления.

### L5 — Subject Response

Результат отдельного исследования с участниками.

L4 → L5 не является автоматическим преобразованием.

---

## 3. Операционное определение экспозиции

Экспозиция не сводится к одному произвольному «баллу интенсивности».

Для программы ω хранится вектор:

Xω(t) = [duration, frequency, recurrence, modality, salience, temporal_concentration, context]

Минимально публикуются:

- начало и конец предъявления;
- суммарная длительность;
- число предъявлений;
- плотность;
- интервалы между предъявлениями;
- визуальная, аудиальная и текстовая модальность;
- мультимодальная одновременность;
- временная концентрация;
- валидированные признаки заметности;
- контекст.

Составной индекс допускается только после публикации формулы, параметров, метода калибровки и эмпирической валидации.

Индекс экспозиции нельзя называть «дозой вреда», пока причинная связь и соответствующая шкала не установлены.

---

## 4. Пороговые понятия

Термин «порог» неоднозначен. Система различает:

1. **Detection threshold** — минимальный уровень стимула для обнаружения.
2. **Discrimination threshold** — минимальная различимая разница между стимулами.
3. **Subjective-response threshold** — уровень экспозиции, при котором субъективный outcome изменяется относительно заданного критерия.
4. **Physiological-response threshold** — уровень экспозиции, при котором заранее определённый физиологический outcome изменяется относительно baseline/control.
5. **Behavioural-response threshold** — уровень экспозиции, связанный с изменением заранее определённого поведения.
6. **Clinically meaningful threshold** — отдельно обоснованная клиническая или функциональная граница.

Эти пороги не взаимозаменяемы.

Порог — параметр конкретного стимула, outcome, метода и популяции, а не универсальная константа человека.

Общая модель:

P(Y | C, X, S, H, Z)

где:

- C — контент;
- X — экспозиция;
- S — текущее состояние;
- H — история/предшествующий опыт;
- Z — индивидуальные и контекстные ковариаты.

Если данные не позволяют надёжно оценить порог, результат публикуется как:

**«Порог не оценён».**

---

## 5. Response Profile

До сбора данных должны быть определены:

- primary outcome;
- secondary outcomes;
- baseline window;
- stimulus window;
- recovery window;
- preprocessing;
- критерии исключения;
- статистическая модель;
- правила работы с пропусками.

Возможные измерения:

- EDA;
- HR / HRV;
- respiration;
- temperature;
- EMG;
- eye tracking;
- pupilometry;
- EEG;
- fMRI в специализированных лабораторных исследованиях;
- субъективная валентность и arousal;
- поведенческие показатели.

Для временных рядов могут использоваться peak, latency, area-under-the-curve и recovery time.

Один физиологический канал не объявляется универсальным измерителем «возбуждения организма».

---

## 6. Экспериментальный дизайн

Базовая схема:

BASELINE → STIMULUS / CONTROL → RESPONSE → RECOVERY

При возможности предпочтительны:

- within-subject comparison;
- рандомизация или counterbalancing;
- контрольный стимул;
- одинаковые условия предъявления;
- фиксация исходного состояния;
- preregistration;
- заранее определённый primary outcome;
- заранее определённые критерии исключения;
- анализаторское ослепление, если осуществимо;
- обоснование размера выборки;
- публикация effect size и uncertainty;
- контроль множественных сравнений.

Для исследований с участниками требуются соответствующая этическая оценка, информированное согласие, право на прекращение участия и процедуры минимизации риска.

---

## 7. Оценка порога и exposure-response

Вместо произвольной границы предпочтительно исследовать функцию:

P(response | X) = f(X; θ)

В зависимости от outcome могут применяться:

- psychometric curves;
- logistic/probit models;
- generalized additive models;
- mixed-effects models;
- hierarchical Bayesian models.

Для каждого порога публикуются:

- операциональное определение;
- outcome;
- модель;
- estimator;
- единицы экспозиции;
- population;
- confidence/credible interval;
- diagnostics;
- sensitivity analysis.

Порог одной выборки нельзя автоматически превращать в универсальный порог.

---

## 8. Индивидуальная вариативность

Проект исходит из неоднородности субъектов.

Для повторных измерений предпочтительны mixed-effects / hierarchical models.

Пример:

Yij = β0 + β1Xij + ui + εij

где ui — subject-specific random effect.

При необходимости учитываются заранее определённые ковариаты: состояние, внимание, история экспозиции, характеристики стимулов и другие факторы.

Результат группы не должен автоматически интерпретироваться как результат каждого отдельного человека.

---

## 9. Потенциально деструктивные социальные программы

Это онтологическая исследовательская категория, а не моральная оценка.

Процедура:

OBSERVATION → PROGRAM DETECTION → EXTERNAL EVIDENCE → RISK CLAIM

### Program detection

Фиксирует наличие повторяющейся поведенческой или социальной структуры.

### External evidence

Независимая доказательная база по конкретному исходу, популяции и условиям.

### Risk claim

Допускается только с указанием:

- исхода;
- популяции;
- условий;
- качества доказательств;
- ограничений;
- альтернативных объяснений;
- даты обзора доказательств.

Наличие MPE не является доказательством риска.

---

## 10. Контекст

Контекст хранится как многомерный вектор:

K_i = [consequence, representation, actor_role, camera_emphasis, social_reaction, verbal_context, music, recurrence, narrative_role]

Каждая ось получает:

- операциональное определение;
- допустимые значения;
- confidence;
- источник наблюдения;
- версию разметки.

Составные понятия вроде «романтизация» не должны становиться единственной меткой, если их можно разложить на наблюдаемые компоненты.

---

## 11. Метрики

Для программы ω:

- Nω — число событий;
- Tω — суммарная длительность;
- Sω — time share;
- Cω — shot coverage;
- ρω — event density;
- Rω — recurrence.

Time share:

Sω = Σ(Δtᵢ pᵢω) / T

Co-occurrence:

Mωψ = Nω∩ψ / Nω∪ψ

Co-occurrence — структурная совстречаемость, а не причинная связь.

Программы могут пересекаться, поэтому их доли не обязаны суммироваться до 100%.

---

## 12. Валидация

### Gold-standard corpus

Набор произведений/фрагментов с независимой экспертной разметкой по опубликованному codebook.

### Межэкспертное согласие

В зависимости от структуры данных:

- Cohen’s κ;
- Fleiss’ κ;
- Krippendorff’s α.

### Валидация моделей

Публикуются:

- precision;
- recall;
- F1;
- confusion matrix;
- calibration;
- sensitivity/specificity, когда применимо;
- ошибки по типам контента и релевантным подгруппам.

### Ошибки

Минимально разделяются:

- model error;
- annotation error;
- sampling uncertainty;
- measurement error.

Нельзя просто складывать эти компоненты в один показатель без обоснованной модели распространения неопределённости.

---

## 13. Культурная и языковая валидность

Онтология имеет уровни:

- Level 1 — максимально переносимая категория;
- Level 2 — региональный/культурный подтип;
- Level 3 — локальный специализированный подтип.

Для многоязычного контента:

original speech → transcription → linguistic analysis → optional translation

Оригинальный сигнал сохраняется, если это возможно. Перевод является отдельным преобразованием с собственной неопределённостью.

## 14. Воспроизводимость

Каждый анализ хранит:

- content_hash;
- точную версию медиафайла;
- ontology_version;
- annotation_schema_version;
- vision_model_version;
- audio_model_version;
- nlp_model_version;
- preprocessing configuration;
- measurement parameters;
- statistical model;
- random seed, если применимо;
- software/environment version;
- timestamp;
- analysis hash.

Концептуально:

H = SHA256(content_hash || versions || parameters || code_version)

Точная сериализация должна быть стандартизирована до production.

Различаются:

- deterministic reproducibility;
- statistical reproducibility;
- independent replication.

## 15. Content Passport 3.0

Паспорт состоит из независимых слоёв.

### Metadata layer

- идентификация;
- названия и даты;
- языки и страны;
- тип;
- создатели;
- актёры;
- сюжетные и жанровые метаданные;
- награды;
- технические данные;
- источники и даты синхронизации.

### Measurement layer

- ontology;
- MPE;
- N/T/S/C/ρ/R;
- context vector;
- temporal map;
- co-occurrence network;
- exposure profile;
- uncertainty;
- validation summary;
- model/protocol versions.

Связь:

content_id + content_hash

Метаданные и измерения не смешиваются в одну семантическую таблицу.

---

## 16. Provenance метаданных

Каждое поле метаданных должно хранить:

- source;
- retrieved_at;
- source_version, если доступна;
- confidence;
- conflict_status;
- human_verified.

«Источник истины» определяется отдельно для каждого поля.

При существенном конфликте:

needs_review = true

Значение нельзя молча заменять другим.

---

## 17. Экранное время актёров

Экранное время является вычисляемой оценкой.

Пайплайн:

FACE DETECTION → TRACKING → EMBEDDING / IDENTIFICATION → CLUSTERING → CAST ASSIGNMENT → AGGREGATION

Публикуются:

- метод;
- модель и версия;
- confidence;
- validation metrics;
- uncertainty;
- правила частично закрытого лица;
- групповые сцены;
- грим и маски;
- дублёры и каскадёры;
- CGI и виртуальные персонажи.

Без validation экранное время не публикуется как точный установленный факт.

## 18. Метаданные и права

Система различает:

- фактические метаданные;
- лицензируемые изображения;
- пользовательские аннотации;
- производные вычисляемые показатели;
- ссылки на внешние источники.

Наличие URL изображения не означает права на его републикацию.

## 19. Этика исследований

Исследования с участниками должны учитывать:

- информированное согласие;
- право отказаться;
- оценку риска;
- этическое одобрение там, где оно требуется;
- debriefing, если процедура его требует;
- минимизацию персональных данных;
- безопасное хранение физиологических данных;
- минимизацию идентифицируемости.

Чувствительные стимулы требуют дополнительных мер защиты.

## 20. Falsifiability

Проверяемые гипотезы:

### H1
Контентные признаки можно формализовать с воспроизводимым межэкспертным согласованием.

### H2
Некоторые конфигурации медиастимула вызывают измеримые изменения заранее определённых response outcomes относительно контроля.

### H3
Величина или вероятность реакции зависит от параметров экспозиции для некоторых классов стимулов.

### H4
Параметры реакции и пороги различаются между субъектами.

### H5
Контекст и сочетание стимулов модифицируют response profile.

Каждая гипотеза должна иметь заранее определённый outcome, критерий проверки и план анализа.

---

## 21. Уровни доказательности

Для публичных утверждений:

- **A — observed:** непосредственно наблюдено в контенте;
- **B — validated measurement:** измерение прошло независимую валидацию;
- **C — experimental response:** реакция показана в контролируемом исследовании;
- **D — causal evidence:** причинный эффект поддержан соответствующим дизайном;
- **E — harm evidence:** неблагоприятный исход подтверждён отдельной доказательной базой.

A не даёт права делать утверждение уровня E.

---

## 22. Публичный вывод

Карточка отвечает на три разных вопроса:

1. Что это за произведение? — Metadata.
2. Что в нём наблюдается и как это измерено? — Contentometry.
3. Что произошло с участниками конкретного исследования? — Response Study.

Response Study публикуется только при наличии реального исследования.

---

## 23. Запрещённые методологические сокращения

Нельзя:

- превращать контентный счётчик в медицинский риск;
- называть произвольный индекс «дозой»;
- выдавать статистическую значимость за практическую значимость;
- выдавать корреляцию за причинность;
- выдавать реакцию одной группы за универсальную реакцию;
- скрывать неопределённость;
- смешивать метаданные и измерения;
- использовать автоматическую классификацию как безошибочный факт;
- превращать систему в автоматическую цензуру или моральный рейтинг.

---

## 24. Минимальный формат публикации

Каждый публичный результат содержит:

CONTENT + METHOD + UNCERTAINTY + VERSION + LIMITATIONS

Результат — воспроизводимая запись того, что конкретная версия системы смогла наблюдать и измерить на конкретной версии произведения.

## 26. Статус

**Scientific Contentometry Protocol v0.2**

Статус: **research protocol / methodological prototype**.

Главная граница проекта:

> Сначала наблюдение. Затем измерение. Затем проверка.
>
> Не превращать гипотезу в факт.
> Не превращать реакцию в вред.
> Не превращать измерение в интерпретацию.

Синема Катарсис остаётся инфраструктурой наблюдаемости медиасреды, а не системой принятия решений за Субъекта.

## 27. Protocol implementation lock — 2026-09-19

Protocol v0.2 является методологическим контрактом исследовательского прототипа.

До появления эмпирической валидации следующие величины считаются **операциональными параметрами исследования**, а не универсальными человеческими константами:

- reaction thresholds;
- exposure indices;
- dose-response functions;
- composite arousal measures.

Любая будущая публикация результата должна указывать:

```
CONTENT + EXPOSURE + RESPONSE + DESIGN + UNCERTAINTY + LIMITATIONS
```

### MVP validation sequence

1. ontology/codebook;
2. independent double annotation;
3. adjudication;
4. locked gold-standard test set;
5. baseline model;
6. precision/recall/F1 + calibration;
7. error analysis;
8. reproducibility package;
9. only then — exposure-response pilot.

Это предотвращает преждевременный переход от философской гипотезы к эмпирическому утверждению.
