# Синема Катарсис: Контентометрия 2.0

## 1. Определение

**Синема Катарсис** — методологическая и программная система контентометрии, предназначенная для формального описания наблюдаемого медиасодержания.

Система строит **Content Map**, а не рейтинг.

Ключевое различие:

- **наблюдение** — что присутствует в медиаматериале;
- **аннотация** — как наблюдение кодируется;
- **измерение** — сколько, как часто и где это происходит;
- **интерпретация** — что это может значить;
- **каузация** — влияет ли содержание на поведение.

Первые четыре уровня нельзя смешивать, а причинность не выводится из самого контентометрического анализа.

---

## 2. Формальные принципы

### 2.1 Наблюдаемость

Элемент считается измеримым, если он:

1. непосредственно наблюдаем; или
2. выводим из наблюдаемого по опубликованному правилу.

Ненаблюдаемая гипотеза не должна записываться как факт.

### 2.2 Разделение уровней

```
L0 Observation
  ↓
L1 Event
  ↓
L2 Media Program Element (MPE)
  ↓
L3 Narrative Relation
```

### 2.3 Неимпликация

Наличие MPE не доказывает:

- авторское намерение;
- одобрение;
- неодобрение;
- воздействие;
- причинность;
- качество;
- моральную или художественную ценность.

### 2.4 Перекрытие

Категории могут совстречаться. Поэтому для разных ω:

```
p(i,ω) ∈ [0,1]
```

и сумма по ω не обязана быть равна 1.

## 3. Единицы анализа

Иерархия:

```
WORK
 └─ SEQUENCE
     └─ SCENE
         └─ SHOT
             └─ FRAME
```

Событие является отдельной семантической сущностью и может пересекать границы монтажных единиц.

Важно:

**SHOT ≠ EVENT**

Один shot может содержать несколько событий, а одно событие может продолжаться через несколько shots.

## 5. Культурная локализация

Онтология должна поддерживать:

```
Universal
  └─ Regional
      └─ Local
```

Пример:

```
consumption.alcohol
consumption.alcohol.beer
consumption.alcohol.beer.local_context
```

Универсальный уровень предназначен для межкультурного сопоставления. Локальные уровни сохраняют культурную специфику.

Культурная специфика не должна автоматически превращаться в моральную оценку.

## 6. Контекст

Одна итоговая метка вроде «романтизация» недостаточна. Контекст хранится как многомерный вектор.

Пример осей:

| Ось | Значения |
|---|---|
| consequence | none / positive / negative / mixed / unknown |
| representation | neutral / attractive / repulsive / comic / dramatic / ambiguous |
| actor_role | hero / antagonist / side / narrator / unknown |
| camera_emphasis | close / medium / wide / offscreen |
| social_reaction | approval / disapproval / ignore / mixed / unknown |
| verbal_context | endorse / condemn / neutral / ambiguous |
| music | tense / light / dramatic / absent / other |
| recurrence | single / repeated / patterned |
| narrative_role | causal / decorative / background / unknown |

Каждая ось имеет собственную confidence/uncertainty.

Система не обязана сводить этот вектор к одной интерпретационной метке.

---

## 7. Основные метрики

Для программы ω:

```
Sω = Σ(Δti · piω) / T
Cω = |{i : piω > 0}| / Nshots
Eω = Nω / Nevents
ρω = Nω / T
Rω = Nω / Nepisodes
```

где:

- S — доля времени;
- C — coverage;
- E — event share;
- ρ — density;
- R — recurrence.

Со-встречаемость:

```
Mωψ = N(ω ∩ ψ) / N(ω ∪ ψ)
```

Это коэффициент Жаккара. Он описывает структурную совстречаемость и не является причинной мерой.

### Важное ограничение Eω

Если события могут иметь несколько меток, знаменатель должен быть явно определён как число **всех событий**, а не сумма событий по категориям. Это предотвращает ложную нормализацию до 100%.

---

## 8. Неопределённость и ошибки

Не следует автоматически считать независимыми источники ошибки и складывать их в корень из суммы квадратов. В реальной системе ошибки могут быть коррелированы.

Поэтому v2 использует общий принцип:

```
uncertainty = propagated uncertainty from
model + annotation + sampling + segmentation + fusion
```

Конкретный способ расчёта выбирается по типу метрики.

Для выборочных оценок предпочтительны bootstrap или другие методы, соответствующие структуре данных.

Для временных рядов учитываются автокорреляция и неоднородность выборки.

---

## 9. Confidence и Accuracy

```
confidence = уверенность модели в конкретной аннотации

precision = TP / (TP + FP)

recall = TP / (TP + FN)

F1 = 2PR / (P + R)
```

Confidence нельзя публиковать как доказательство точности.

Модель валидируется на независимом gold-standard наборе.

Для редких событий дополнительно рассматриваются PR-AUC, а не только accuracy.

---

## 10. Межэкспертное согласие

Для категориальных переменных применяются подходящие меры согласия.

- Cohen's κ — два разметчика;
- Fleiss' κ — несколько разметчиков;
- для порядковых шкал — weighted κ;
- для многомерных/сложных аннотаций при необходимости — Krippendorff's α.

Порог κ < 0.40 не должен автоматически означать «ошибку». Он является сигналом пересмотреть определение категории, обучение разметчиков или саму постановку задачи.

Отчёт должен содержать не только коэффициент, но и:

- число наблюдений;
- распределение классов;
- confusion matrix;
- способ разрешения разногласий.

## 11. Масштабы

```
FRAME
SHOT
EVENT
SCENE
SEQUENCE
WORK
FRANCHISE
CORPUS
ERA
```

Метрики агрегируются иерархически.

Для корпуса:

```
Dω^(k) = Tω^(k) / T^(k)
```

Но агрегирование должно учитывать структуру выборки: один очень длинный фильм не должен автоматически иметь тот же вес, что сотня коротких работ, если исследовательская задача требует равного веса произведений.

Поэтому вводятся разные estimands:

- work-weighted;
- time-weighted;
- episode-weighted;
- audience-weighted — только при наличии независимых данных об аудитории.

## 12. Продольный анализ

Для временных рядов:

```
Sω(y)
```

может анализироваться через:

- абсолютное изменение;
- относительное изменение;
- тренд;
- структурные переломы;
- интервалы неопределённости.

Регрессия:

```
Sω(y) = β0 + β1 y + ε
```

не должна автоматически применяться ко всем рядам. Для нелинейных изменений используются spline/segmented models или другие подходящие модели.

Корреляция двух рядов:

```
ρ(ω,ψ) = corr(Sω(y), Sψ(y))
```

описывает совместное изменение, но не устанавливает причину.

## 15. Репродуцируемость

Каждый анализ содержит:

```
content_hash
ontology_version
schema_version
segmentation_version
vision_model
audio_model
nlp_model
fusion_version
measurement_version
validation_version
parameters
timestamp
analysis_hash
```

Хэш:

```
Hanalysis = SHA256(content_hash || versions || parameters)
```

Цель воспроизводимости — не обещание бит-в-бит одинакового результата при любой аппаратной среде, а заранее установленный tolerance для каждой метрики и детерминированный режим там, где это возможно.

- advertising

## 18. Открытое управление онтологией

Изменения проходят через RFC:

```
proposal
  ↓
public discussion
  ↓
pilot annotation
  ↓
inter-rater validation
  ↓
decision
  ↓
version release
  ↓
optional re-analysis
```

Изменение онтологии не должно молча менять исторические результаты. Старые анализы сохраняют исходную версию.

Допускаются совместимые форки онтологии с собственными идентификаторами.

---

## 19. Этические и исследовательские ограничения

Система не должна:

- маскировать интерпретацию под факт;
- использовать confidence как замену валидации;
- превращать корреляцию в причинность;
- выдавать рейтинг произведений;
- скрывать неопределённость;
- незаметно менять определения категорий;
- использовать автоматическую классификацию как единственный источник истины в спорных случаях.

Контентометрия предназначена для наблюдаемости медиасреды, а не для автоматического управления зрителем.
