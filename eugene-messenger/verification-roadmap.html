Verification Roadmap

Формальная спецификация, модель и реализация не должны смешиваться. Каждая ступень имеет собственный статус доказательности.

Security Invariants

  • PrivateKeyNeverLeavesCore
  • RelayNeverReceivesPlaintext
  • PluginNeverReceivesPrivateKey
  • UnauthorizedCapabilityCannotExecute
  • CapabilityNonEscalation
  • MessageIntegrityIsVerifiable
  • IdentityContinuityIsPreserved
  • PluginIsolationIsMaintained
  • EventAuthorizationIsEnforced
  • AntiReplay и DowngradeResistance
  • RecoverySafety

Protocol Specification

Формализуются handshake, типы сообщений, поля, криптографические переходы, sequence/nonce, replay protection, ошибки, recovery, federation и capability negotiation.

State Machines

Отдельно описываются состояния клиента, relay, federation node и plugin lifecycle: bootstrap, identity loaded, connected, federated, suspended, recovered, revoked, quarantined и shutdown.

Key Lifecycle

Создание, ротация, использование, отзыв, восстановление и уничтожение identity, session и ephemeral keys должны иметь формальные переходы. Отдельно проверяются forward secrecy, post-compromise recovery и downgrade resistance.

Conformance

Цепочка: EPS/specification → formal model → implementation → conformance → adversarial testing → security audit.

Важная граница доказательства

Наличие TLA+, Coq, Iris, прототипа или формального эскиза не является само по себе доказательством безопасности. Для сильных утверждений требуются явные refinement relations, semantic bridge и проверяемая корректность используемого checker.

CI

В перспективе Security CI должен включать model checking, property-based testing, protocol conformance, dependency и supply-chain verification, а также regression tests для негативных и adversarial сценариев.
