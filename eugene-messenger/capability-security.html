Capability Security Model

Недоверенный компонент не получает доверие. Он получает минимально необходимую способность выполнить конкретную операцию.

Capabilities

CapabilityНазначение
ReadMessageЧтение разрешённых сообщений
SendMessageОтправка разрешённых сообщений
ReadMetadataЧтение ограниченного набора метаданных
StorageRead / StorageWriteОграниченное хранилище
CryptoSign / CryptoDecryptЗапрос криптографической операции у Core без передачи ключа
UIAccessОграниченное взаимодействие с интерфейсом
EventSubscribeПодписка только на разрешённые классы событий

Lifecycle

Install → Verify → Grant → Execute → Monitor → Revoke → Quarantine → Remove.

Невозможность эскалации

Capability не может самостоятельно расширить собственный scope. Делегирование должно быть явным. Возможны expiration, revocation и attenuation.

Секреты

Плагин не получает приватный ключ. Вместо прямого доступа используется запрос к Core: Core.Sign(capability_token, data). Результатом является только разрешённый результат операции.

Event Fabric

Плагин получает не весь журнал, а только события, соответствующие его capability scope. Это предотвращает превращение аудита в скрытое централизованное наблюдение.

Non-Interference

Компонент не должен иметь возможности изменять состояние другого субъекта или компонента, если такая возможность не необходима для заявленной функции и явно не предоставлена capability.
