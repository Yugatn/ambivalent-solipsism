Eugene Messenger

Implementation Strategy

Эта дорожная карта не заменяет архитектуру. Она определяет безопасный порядок перехода от исследовательской спецификации к воспроизводимому прототипу.

Правило «сначала модель»

Код критического протокола не должен становиться первичным источником истины. Сначала фиксируется EPS, затем формальная модель, затем reference implementation и только после этого оптимизация.

Rust как reference runtime

Rust может быть целевой реализацией, но конкретные криптографические и сетевые библиотеки не должны считаться частью канона до отдельного анализа их API, security model, maintenance и соответствия протоколу. Eugene Messenger не должен зависеть от предположения, что сторонняя библиотека автоматически наследует все свойства архитектуры.

Cryptographic composition

Не следует просто «собрать» Ed25519, X25519, HKDF и AEAD в собственный протокол. Сначала выбирается и формально фиксируется протокол композиции. Если используется существующий протокол, документируется точная версия и границы модификаций.

Reproducibility

Сборка reference implementation должна быть воспроизводимой настолько, насколько это практически возможно: lockfiles, pinned dependencies, проверяемые артефакты, SBOM и provenance.
