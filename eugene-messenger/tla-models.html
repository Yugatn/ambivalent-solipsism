TLA+ Model Plan

Цель модели — проверять переходы состояния и инварианты, а не имитировать криптографическую стойкость математически.

Handshake

Состояния: Bootstrap, IdentityLoaded, SessionNegotiating, Established, Suspended, Revoked, Recovered.

Anti-Replay

Модель должна включать epoch, sequence context, accepted windows, delayed delivery, duplicate delivery и старые состояния.

Capability lifecycle

Install → Verify → Grant → Execute → Monitor → Revoke → Quarantine → Remove. Проверяются невозможность исполнения после revoke и невозможность повышения capability через переходы.

Recovery

Модель должна различать потерю устройства, компрометацию credential, recovery authorization и выпуск нового доверенного состояния.

Boundaries

TLA+ не доказывает свойства конкретной криптографической примитивной реализации. Для этого нужны отдельные protocol proofs, assumptions и тестирование.
