Assurance Case

Assurance Case связывает security claims с аргументом, evidence, assumptions и residual risk. Это не заявление об абсолютной безопасности.

GOAL
Критические security properties должны быть проверяемыми в пределах явно заданных assumptions.
STRATEGY
Каждый claim проходит цепочку: specification, formal model, implementation, conformance, adversarial testing и независимая проверка.
CLAIM A
Relay не получает plaintext.
Evidence: Trust Model, protocol specification, E2EE conformance tests.
Residual: endpoint compromise и traffic analysis.
CLAIM B
Replay не вызывает повторный state transition.
Evidence: AntiReplay.tla, TLC, property tests, adversarial traces.
Residual: границы модели и корректность authentication.
CLAIM C
Revoked capability не получает новую authority.
Evidence: CapabilityLifecycle.tla и runtime tests.
Residual: компрометация host/runtime.

Статусы

planned означает запланировано; specified означает зафиксировано; model_checked означает проверено моделью; conformant означает подтверждено соответствие реализации; audited означает независимо проверено. Статус не повышается без соответствующего evidence.

Правило честного assurance

Отсутствие evidence не является evidence. Модель не заменяет реализацию, benchmark не заменяет proof, а audit не устраняет residual risk.
