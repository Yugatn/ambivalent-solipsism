# Project Memory · Сюжет Икс / Амбивалентный Солипсизм

## Назначение

Этот файл — внешняя долговременная память проекта. Он хранит устойчивые правила, авторские предпочтения, важные исправления и решения, которые нужно учитывать при дальнейшей работе с репозиторием.

Это не системная память ChatGPT и не заменяет контекст текущего диалога. Файл предназначен для восстановления проектного контекста в будущих сессиях.

## Авторские правила

1. Югатн — автор «Амбивалентного Солипсизма» и «Сюжета Икс».
2. Не называть «Амбивалентный Солипсизм» квантовым солипсизмом.
3. В авторском литературном тексте предпочитать полное название «Амбивалентный Солипсизм», а не сокращения.
4. При обращении к читателю использовать уважительные формы с прописной буквы: «Вы», «Ваш», «Вам», «Вас», «Ваше», «Вашей», «Вашими».
5. Технические модели могут использоваться как основание для понимания, но в читательском тексте должны быть переведены на естественный философский и литературный язык, если их публикация в исходной формальной форме не является частью замысла.
6. Не превращать художественный текст в техническую документацию без прямого запроса.
7. В новых главах и редакциях не использовать стрелочные схемы как замену повествованию; смысл должен быть выражен прозой.
8. Не делать метафизические утверждения сильнее, чем позволяет сам текст. Формализация может дисциплинировать рассуждение, но не должна автоматически объявляться доказательством метафизической истины.

## Правила работы с GitHub

1. Перед каждым изменением, созданием, удалением или коммитом файла в GitHub необходимо показать пользователю точное предлагаемое содержимое или точный код изменения и получить явное подтверждение.
2. После подтверждения можно выполнять запись.
3. Чтение и аудит GitHub можно выполнять без предварительного подтверждения.
4. Не удалять и не изменять случайно созданные материалы без отдельного предложения и подтверждения пользователя.
5. Особенно важно: глава 09 была создана ранее без отдельного подтверждения пользователя. Не удалять и не редактировать её молча.

## «Сюжет Икс»: редакционная политика

- Проект является художественно-философским произведением, а не техническим отчётом.
- Технические конструкции, включая формальные модели, используются как интеллектуальный каркас и могут быть преобразованы в повествовательную форму.
- Материалы, которые пользователь передаёт исключительно для понимания архитектуры или идеи, не следует автоматически публиковать в книге.
- Рабочие пометки, редакторские инструкции, TODO, внутренние комментарии и технические артефакты не должны попадать в финальный читательский текст.
- Сохранять неоднозначность там, где она является частью авторского замысла.
- Не упрощать философские идеи до банальных мотивационных формул.
- Сохранять центральную тему: восприятие, субъектность, другой субъект, продолжение, изменение, память, реальность и границы модели.

## Важные технические решения веб-читателя

В `story-x/index.html` уже исправлены критические проблемы:

- Markdown-файл загружается через `fetch('./probuzhdenie.md?...')`.
- Разбор строк использует `md.split(/\r?\n/)`, что устраняет проблему с CR/LF.
- Регулярное выражение для формульных строк использует экранированные звёздочки.
- Функция `inline()` корректно обрабатывает жирный, курсив и жирный курсив.
- Навигация по карте сюжета строится динамически по заголовкам `h2`.
- Переход к разделу использует `scrollIntoView`.
- Оглавление в `details` закрывается после выбора раздела.
- Есть мобильная адаптация.
- При ошибке загрузки текста показывается ссылка на прямое открытие Markdown-файла.

## Последние важные редакционные решения

1. Из `probuzhdenie.md` удалены рабочие редакторские пометки, включая пометку о рабочей редакции и строки «Драматургическая задача».

3. Очевидные технические идентификаторы и англоязычные названия в читательском тексте заменены естественными русскими формулировками.
4. Большие стрелочные диаграммы и формальные системные проекции заменены связной прозой.
5. Раздел «Формальные инварианты» переписан как философское рассуждение без публикации исходного TLA+ кода.
6. Технические формальные материалы пользователя следует считать контекстом проекта, пока пользователь явно не решит опубликовать их в книге.

## Формальные идеи проекта, которые важно сохранять

- Различать состояние субъекта и возможность дальнейшего изменения.
- Не сводить непрерывность субъекта к неизменности конкретного состояния.
- Различать научную модель и метафизическую интерпретацию.
- Рассматривать инвариант как свойство, сохраняющееся при определённом классе преобразований.
- Сохранять идею, что изменение не тождественно разрушению, а продолжение не тождественно сохранению.
- Не выдавать формальную модель за доказательство бессмертия или иной метафизической гипотезы.
- Сохранять принцип «Сложность — не ошибка. Другой — реален.»
