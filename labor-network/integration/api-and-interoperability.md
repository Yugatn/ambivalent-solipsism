# API и межсистемное взаимодействие

СТСеть должна взаимодействовать с другими системами без превращения одной платформы в обязательный центр всей информации.

## 1. Контракты

Каждый внешний интерфейс описывает:

- схему;
- версию;
- назначение;
- допустимые поля;
- ошибки;
- ограничения;
- политику совместимости.

## 2. Data minimization by API

API должен позволять запросить минимально необходимое представление данных.

Полный профиль не является значением по умолчанию.

## 3. Capability-based access

Внешней системе передаётся конкретная capability, а не универсальный доступ к субъекту.

## 4. Federation

Региональные, государственные, образовательные и трудовые узлы могут оставаться автономными.

Федерация обеспечивает совместимость, а не централизованное хранение всего.

## 5. Failure isolation

Сбой одного узла не должен автоматически останавливать всю сеть.

## 6. Version compatibility

Изменение API должно иметь период совместимости и понятный путь миграции.

## 7. Принцип

> Совместимость систем не требует централизации их данных.
