# Content-Level Audit СТСети

Цель аудита — проверить перенос не по именам файлов, а по смысловым блокам.

## Метод

Для каждого исходного документа фиксируются:

- source file;
- source section;
- preserved concept;
- destination module;
- transformation;
- new constraints;
- test/reference.

## Статусы

- preserved — перенесено без существенного изменения;
- refined — смысл сохранён и уточнён;
- decomposed — исходный блок распределён по нескольким модулям;
- extended — сохранён и дополнен;
- pending — требует ручной проверки.

## Правило

Отсутствие буквального совпадения текста не считается потерей, если исходная семантика представлена в новой структуре и существует трассируемая связь.

## Контроль

Каждый pending-блок должен получить destination или быть явно признан историческим/устаревшим материалом.

## Запрет silent loss

Ни один существенный исходный принцип не может исчезнуть только вследствие реорганизации.
