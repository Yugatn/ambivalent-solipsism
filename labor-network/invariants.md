# Формальные инварианты СТСети

Инвариант — условие, которое система не должна нарушать даже при изменении состояния.

## I1. Subjecthood

Ни один технический статус не является универсальной оценкой человеческой ценности.

## I2. Purpose limitation

Данные не используются для существенной новой цели без отдельного основания.

## I3. Provenance

Существенное решение должно иметь проверяемую связь с использованными данными и правилами.

## I4. Contestability

Существенный вывод может быть оспорен через предусмотренный механизм.

## I5. Reversibility

Временное ограничение не становится постоянным автоматически.

## I6. Minimal disclosure

Передаётся минимально необходимый набор данных.

## I7. Separation

Идентичности и функциональные контексты не объединяются без необходимости.

## I8. No silent escalation

Система не расширяет свои полномочия только потому, что получила новые данные.

## I9. Error propagation control

Исправление существенной исходной ошибки инициирует проверку зависимых выводов.

## I10. Availability

Отказ отдельного узла не должен без необходимости лишать субъекта всей трудовой истории или критического сервиса.

## I11. Human review

Для заранее определённых высокоэффектных решений существует механизм пересмотра.

## I12. Exit

Участник может завершить необязательное взаимодействие и получить информацию о последствиях выхода.

## I13. Collective autonomy

Коллективные механизмы не отменяют индивидуальную субъектность.

## I14. Infrastructure neutrality

Инфраструктурный дефицит не должен автоматически интерпретироваться как дефект субъекта.

## I15. Unknown preservation

Неизвестное сохраняется как неизвестное и не превращается автоматически в отрицательный факт.
