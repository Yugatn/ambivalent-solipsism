# Безопасность и государственная интеграция

СТСеть должна соединять удобство единой инфраструктуры с защитой субъектности.

## Уровни данных

- публичная информация;
- профессиональная информация;
- личная информация;
- защищённый государственный контур;
- аудитный контур.

Разделение уровней не должно быть только визуальным: для каждого уровня должны существовать технические правила доступа.

## Принципы

- минимизация данных;
- разграничение доступа;
- контекстность;
- журналирование;
- исправление;
- апелляция;
- ограничение срока хранения;
- защита чувствительных данных;
- проверяемость критических действий.

Медицинские и психологические сведения не должны становиться обычным кадровым досье.

## Цель доступа

Для существенного доступа система должна уметь ответить:

1. кто запрашивает данные;
2. какие именно данные запрашиваются;
3. зачем они нужны;
4. на каком основании предоставляются;
5. на какой срок;
6. какое действие будет выполнено;
7. как субъект может оспорить использование.

## Единый контур обмена данными рынка труда

Вместо «поглощения» существующих сервисов используется совместимость через стандарты и API.

СТСеть может взаимодействовать с существующими площадками и государственными системами, не требуя уничтожения всех независимых интерфейсов.

## Однократное предоставление

После подтверждения трудового события необходимые сведения могут передаваться соответствующим системам в пределах их полномочий.

Человек не должен многократно вводить одну и ту же информацию только из-за несовместимости информационных систем.

Однократность ввода не означает однократность контроля доступа: каждое новое использование данных должно иметь собственное основание и контекст.

## Аудит доступа

Для чувствительных данных желательно фиксировать:

- субъект доступа;
- время;
- категорию данных;
- основание;
- выполненное действие;
- результат.

Доступ без необходимости не должен становиться невидимым для системы аудита.

## PICCS и EthicalAudit

Критические действия должны иметь основание, контекст, журнал и возможность пересмотра.

Обнаружение нарушения не равно автоматически принятому решению.

EthicalAudit может обнаружить сигнал; PolicyEngine определяет допустимое действие; Audit фиксирует исполнение; Appeal предоставляет путь пересмотра.

## Совместимость и отказ

Если внешний сервис временно недоступен, система должна ясно показывать состояние операции и не создавать ложное впечатление успешной передачи данных.

Критические действия должны быть повторяемыми или иметь безопасный способ восстановления.
