# Информационная архитектура СТСети

СТСеть разделяет данные по происхождению, назначению, времени действия и степени подтверждения.

## 1. Сущность данных

Минимальная модель различает:

- субъект;
- организация;
- роль;
- возможность;
- договор;
- навык;
- подтверждение;
- событие;
- решение;
- программу;
- инфраструктурный ресурс;
- спор;
- поддержку.

## 2. Факт и утверждение

Система различает:

- подтверждённый факт;
- заявление субъекта;
- заявление другой стороны;
- автоматический сигнал;
- вывод;
- решение.

Эти типы не должны автоматически преобразовываться друг в друга.

## 3. Происхождение

Существенная запись должна по возможности иметь provenance:

- источник;
- время;
- контекст;
- способ получения;
- версию;
- уровень подтверждения;
- исправления.

## 4. Временность

Данные могут быть:

- действующими;
- историческими;
- истёкшими;
- оспариваемыми;
- отозванными;
- неизвестными.

Отсутствие актуальности не равно ложности исторической записи.

## 5. Производные данные

Расчётный показатель должен быть отличим от исходных данных.

Если изменились исходные данные, система должна уметь определить зависимые производные показатели.

## 6. Контекст

Один факт может иметь разное значение в разных процессах.

Навык, подтверждённый для одной задачи, не становится автоматически подтверждением пригодности для всех задач.

## 7. Минимизация

Для каждой функции определяется минимальный набор данных.

Наличие данных в системе не является основанием использовать их в новом процессе.

## 8. Переносимость

Субъект должен иметь возможность получить понятное представление о существенной части собственной профессиональной истории и, где допустимо, перенести её.

## 9. Неопределённость

Система должна уметь хранить состояние «неизвестно».

Неизвестное не следует автоматически заменять нулём, отказом или отрицательной характеристикой.
