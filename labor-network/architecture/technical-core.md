# Техническое ядро СТСети

Техническое ядро реализует принципы сети как проверяемые состояния, события и ограничения.

## 1. Event-first

Существенные изменения представлены событиями:

- создано;
- подтверждено;
- изменено;
- оспорено;
- ограничено;
- отозвано;
- завершено.

Состояние является результатом последовательности допустимых событий.

## 2. Append-only provenance

История существенных событий не должна молча переписываться.

Исправление создаёт новое событие, связанное с предыдущим.

## 3. State machine

Для каждого типа сущности определяются:

- допустимые состояния;
- допустимые переходы;
- необходимые условия;
- ответственный контур;
- возможность отката или восстановления.

## 4. Идемпотентность

Повторная доставка одного и того же события не должна создавать двойной экономический или правовой эффект.

## 5. Версионирование

Правила и схемы должны иметь версии.

Решение должно быть воспроизводимо настолько, насколько это возможно.

## 6. Fail-safe

При неопределённости система должна предпочитать безопасное ограничение действия, а не расширение полномочий.

## 7. Human override

Для существенных решений должен существовать предусмотренный механизм человеческого пересмотра.

## 8. Bounded automation

Автоматизация ограничивается конкретной функцией и не получает право самостоятельно расширять собственную область применения.
