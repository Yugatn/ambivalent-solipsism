# Content-Level Audit СТСети

Цель аудита — проверить перенос не по именам файлов, а по смысловым блокам.

## Метод

Для каждого исходного документа фиксируются:

- source file;
- source section;
- preserved concept;
- destination module;
- transformation;
- new constraints;
- test/reference.

## Статусы

- **preserved** — перенесено без существенного изменения;
- **refined** — смысл сохранён и уточнён;
- **decomposed** — исходный блок распределён по нескольким модулям;
- **extended** — сохранён и дополнен;
- **pending** — требует ручной проверки.

Для совместимости с более детальной классификацией миграции также используются migrated, refined, merged и index.

## Правило

Отсутствие буквального совпадения текста не считается потерей, если исходная семантика представлена в новой структуре и существует трассируемая связь.

## Контроль

Каждый pending-блок должен получить destination или быть явно признан историческим или устаревшим материалом.

Для каждого legacy-файла проверяются назначение, нормативные принципы, доменные понятия, ограничения, lifecycle, evidence, audit-требования, связанные документы и отсутствие противоречий.

Если один legacy-фрагмент распределён по нескольким новым файлам, это считается корректной миграцией при наличии traceability.

## Запрет silent loss

Ни один существенный исходный принцип не может исчезнуть только вследствие реорганизации.

## Current checkpoint

Файловое покрытие: **100%**.

Семантическое покрытие проверяется отдельно до завершения полного content-level audit.

Legacy-файлы сохраняются до окончания content-level audit.
